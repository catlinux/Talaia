# Internationalization (i18n)

[Leer en castellano](../es/i18n.md) · [Back to README](../../README.md)

Talaia's interface is available in **Catalan (`ca`)**, **Spanish (`es`)** and **English (`en`)**. This
guide defines how translations work in every component.

## 1. Rules

1. **No hard-coded user-facing text.** Every string a user can see (UI, API error messages, CLI output,
   notification texts, emails) uses a translation key.
2. **All three languages, always.** A key that is missing in `ca`, `es` or `en` fails CI.
3. **English is the fallback** if a key or a language is not available at runtime.
4. **Catalan is the reference language for the UI:** new texts are usually written first in Catalan, then
   in Spanish and English. Any of the three may be written first, but all three go in the same commit.
5. **Logs are not translated.** Technical logs of the core and the agent are always in English.
6. Dates, times, numbers and sizes are formatted with the active locale (`Intl` in the browser).

## 2. Language selection

Order of preference:

1. Language saved in the user profile (`user.locale`)
2. Language chosen in the panel (stored in the browser)
3. Browser language (`navigator.languages`)
4. English (`en`)

The CLI uses `--lang`, then `TALAIA_LANG`, then `LANG`/`LC_ALL`, then English.

## 3. Web panel (`web/`)

Libraries: `i18next`, `react-i18next`, `i18next-browser-languagedetector`.

```
web/src/locales/
├─ ca/
│  ├─ common.json     # buttons, states, navigation
│  ├─ fleet.json
│  ├─ server.json
│  ├─ stack.json
│  ├─ auth.json
│  └─ errors.json     # API error codes
├─ es/  (same files)
└─ en/  (same files)
```

Example, `web/src/locales/ca/fleet.json`:

```json
{
  "title": "Flota",
  "kpi": {
    "serversOnline": "Servidors en línia",
    "securityUpdates_one": "{{count}} actualització de seguretat",
    "securityUpdates_other": "{{count}} actualitzacions de seguretat"
  },
  "server": {
    "status": {
      "online": "En línia",
      "offline": "Sense connexió",
      "rebootRequired": "Cal reiniciar"
    }
  }
}
```

Usage:

```tsx
const { t } = useTranslation("fleet");
<h1>{t("title")}</h1>
<span>{t("kpi.securityUpdates", { count: 7 })}</span>
```

## 4. API errors

The core never sends translated sentences to the panel. It sends a **stable code** and parameters; the
panel translates them with the `errors` namespace.

```json
{ "error": { "code": "server.notFound", "params": { "name": "vps-web-01" } } }
```

`errors.json` (es): `"server": { "notFound": "No se encuentra el servidor {{name}}" }`

## 5. Go components (core, CLI)

Library: `github.com/nicksnyder/go-i18n/v2`. Files in `core/i18n/locales/{ca,es,en}.toml` and
`cli/i18n/locales/{ca,es,en}.toml`, embedded with `embed`. Used for texts generated on the server side:
notification messages, emails and CLI output.

The agent does not show text to users, so it has no translations.

## 6. Key naming

- `namespace` = screen or area (`fleet`, `server`, `stack`, `auth`, `common`, `errors`).
- Keys in `camelCase`, nested by component: `server.tabs.packages`.
- Plurals with i18next suffixes: `_one`, `_other` (and `_zero` if needed).
- Interpolation with `{{name}}`. Never build sentences by concatenating translated fragments.
- Do not reuse a key for two different meanings, even if the English text is the same.

## 8. Checks

- `make i18n-check` (from phase 0) compares the key sets of `ca`, `es` and `en` and fails if they differ.
- The CI runs this check on every pull request.
