# Internacionalización (i18n)

[Read in English](../en/i18n.md) · [Volver al README](../../README.es.md)

La interfaz de Talaia está disponible en **catalán (`ca`)**, **castellano (`es`)** e **inglés (`en`)**.
Esta guía define cómo funcionan las traducciones en cada componente.

## 1. Normas

1. **Nada de texto fijo visible para el usuario.** Todo texto que un usuario pueda ver (interfaz,
   mensajes de error de la API, salida de la CLI, notificaciones, correos) usa una clave de traducción.
2. **Siempre los tres idiomas.** Una clave que falte en `ca`, `es` o `en` hace fallar el CI.
3. **El inglés es el idioma de reserva** si una clave o un idioma no está disponible en tiempo de ejecución.
4. **El catalán es el idioma de referencia de la interfaz:** los textos nuevos se suelen escribir primero
   en catalán y después en castellano e inglés. Se puede empezar por cualquiera, pero los tres van en el
   mismo commit.
5. **Los logs no se traducen.** Los logs técnicos del núcleo y del agente son siempre en inglés.
6. Fechas, horas, números y tamaños se formatean con el idioma activo (`Intl` en el navegador).

## 2. Elección del idioma

Orden de preferencia:

1. Idioma guardado en el perfil del usuario (`user.locale`)
2. Idioma elegido en el panel (guardado en el navegador)
3. Idioma del navegador (`navigator.languages`)
4. Inglés (`en`)

La CLI usa `--lang`, después `TALAIA_LANG`, después `LANG`/`LC_ALL` y, si no, inglés.

## 3. Panel web (`web/`)

Bibliotecas: `i18next`, `react-i18next`, `i18next-browser-languagedetector`.

```
web/src/locales/
├─ ca/
│  ├─ common.json     # botones, estados, navegación
│  ├─ fleet.json
│  ├─ server.json
│  ├─ stack.json
│  ├─ auth.json
│  └─ errors.json     # códigos de error de la API
├─ es/  (mismos archivos)
└─ en/  (mismos archivos)
```

Ejemplo, `web/src/locales/es/fleet.json`:

```json
{
  "title": "Flota",
  "kpi": {
    "serversOnline": "Servidores en línea",
    "securityUpdates_one": "{{count}} actualización de seguridad",
    "securityUpdates_other": "{{count}} actualizaciones de seguridad"
  },
  "server": {
    "status": {
      "online": "En línea",
      "offline": "Sin conexión",
      "rebootRequired": "Reinicio necesario"
    }
  }
}
```

Uso:

```tsx
const { t } = useTranslation("fleet");
<h1>{t("title")}</h1>
<span>{t("kpi.securityUpdates", { count: 7 })}</span>
```

## 4. Errores de la API

El núcleo nunca envía frases traducidas al panel. Envía un **código estable** y parámetros; el panel los
traduce con el espacio de nombres `errors`.

```json
{ "error": { "code": "server.notFound", "params": { "name": "vps-web-01" } } }
```

`errors.json` (es): `"server": { "notFound": "No se encuentra el servidor {{name}}" }`

## 5. Componentes en Go (núcleo, CLI)

Biblioteca: `github.com/nicksnyder/go-i18n/v2`. Archivos en `core/i18n/locales/{ca,es,en}.toml` y
`cli/i18n/locales/{ca,es,en}.toml`, incrustados con `embed`. Se usan para textos generados en el
servidor: notificaciones, correos y salida de la CLI.

El agente no muestra texto a los usuarios, así que no tiene traducciones.

## 6. Nombres de claves

- `namespace` = pantalla o área (`fleet`, `server`, `stack`, `auth`, `common`, `errors`).
- Claves en `camelCase`, anidadas por componente: `server.tabs.packages`.
- Plurales con los sufijos de i18next: `_one`, `_other` (y `_zero` si hace falta).
- Interpolación con `{{name}}`. Nunca construyas frases concatenando fragmentos traducidos.
- No reutilices una clave para dos significados distintos, aunque el texto en inglés coincida.

## 8. Comprobaciones

- `make i18n-check` (desde la fase 0) compara las claves de `ca`, `es` y `en` y falla si no coinciden.
- El CI ejecuta esta comprobación en cada pull request.
